# Как участвовать в разработке

Спасибо, что дорабатываете проект. Ниже — короткие правила, чтобы код оставался
рабочим, а история git — понятной.

## 1. Перед первым pull request

1. Подпишите [`CLA.md`](CLA.md) и передайте подписанный экземпляр владельцу
   репозитория (скана/фото с подписью достаточно).
2. Попросите владельца добавить вас в коллабораторы
   (**Settings → Collaborators → Add people**, роль **Write**).
   Либо работайте через форк и PR — как удобнее.

## 2. Окружение

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -r WIN\hand_control\requirements.txt
```

Python 3.10–3.14, Windows 10/11 — основная платформа.
Модели (`*.task`, Vosk) не коммитятся: они скачиваются при первом запуске.

## 3. Ветки и коммиты

- Ветка от `main`: `feature/short-name`, `fix/short-name`, `docs/short-name`.
- В `main` — только через Pull Request. Прямой push в `main` не используем.
- Один PR = одна задача. Не смешивайте рефакторинг и новую функцию.
- Сообщения коммитов — в императиве, на русском или английском, но единообразно:

```
feat: голосовая команда "следующий рабочий стол"
fix: щипок срабатывает при сжатом безымянном пальце
docs: описал установку на Arch
```

- Не коммитьте `__pycache__/`, `*.pyc`, `*.task`, `hand_settings.json`, `darts_best.json`.
  Если файл уже попал в индекс: `git rm --cached <файл>`.

## 4. Стиль кода

- PEP 8, 4 пробела, длина строки ~120 символов (как в существующих файлах).
- Комментарии и докстринги — по-русски, как в проекте; имена переменных — латиницей.
- Не переименовывайте существующие функции без необходимости: на них завязаны игры
  (`hand_control.py` импортируется из `darts_game.py`, `jedi_duel.py`, `emotion_67.py`).
- Любая новая зависимость — в `WIN/hand_control/requirements.txt` с пояснением в PR.
- Не добавляйте сетевые вызовы и телеметрию: приложение должно работать офлайн.

## 5. Проверка перед PR

- [ ] Приложение запускается: `python hand_control.py`
- [ ] Проверены затронутые сценарии (жесты / голос / игра)
- [ ] В `git status` нет мусора и моделей
- [ ] Описание PR: что сделано, как проверить, скриншот/GIF для UI-изменений

## 6. Сообщения об ошибках

Присылайте в Issues по шаблону: версия Windows, версия Python, что делали,
что ожидали, что получилось, текст ошибки из консоли и (если можно) скриншот.

## 7. Права на код

Проект проприетарный (см. [`LICENSE`](LICENSE)). Отправляя PR, вы подтверждаете,
что это ваш код и что вы согласны с условиями [`CLA.md`](CLA.md).
